GOAL (owner's words, summarized): Business section works identically online
and offline; all Business data stored only on devices; the server is only a
relay/waiting station that deletes data once every party received it.
Conflicts: the operation that reaches the server first wins; the other is
cancelled and its author gets a system notice naming who was first. Only
true conflicts (same remaining stock/cash/debt, same unique record, removed
permission) — normal concurrent sales are not conflicts.

ARCHITECTURE (what exists now)
1) Device sync engine — lib/features/core_business/data/local_directory/
   business_sync_engine.dart (part of directory_database.dart, schema v17)
   - TEMP triggers capture every write made through DirectoryDatabase._transaction
     into one operation (outbox). Counter columns merge as deltas.
   - Rules (same decision on every device, by relay sequence): floors (stock,
     lots, cash unless allow_negative, debts/invoices over-paid, employee
     debts), duplicates (bank/cash slot), constraint collisions (later loses),
     employee permissions as of that sequence, cascade to dependants.
   - Notices -> notifications list (notifications_providers.dart).
   - Snapshot hand-over for new/absent devices (employee copy branch-limited).
2) Business relay — backend/app/domain/services/business_relay.py,
   API /api/v1/business-relay/* (register/push/pull(long-poll)/ack/
   snapshot/request|serve|applied/retire/replicas). App worker:
   lib/features/core_business/presentation/providers/business_sync_provider.dart
3) Whole-organization local mode — backend/app/core/business_local_mode.py
   (invited QA owners + the managed pinned QA account; employees of such orgs
   via qa_member claim). Switch: FYONA_QA_LOCAL_ALL_BRANCHES=0 restores the
   old per-branch fence. Device-born branches register id+name (POST /branches).
4) Employees on devices — business_employees_local.dart (table
   business_employees), employee_api.dart routes CRUD locally and syncs
   identity/permissions to the server when online; linking stays online.
5) Peer relay (merchant <-> linked party) — business_peer_relay.py,
   API /api/v1/peer-relay/*; merchant pushes debt copies
   (business_party_sharing.dart); customer stores them (personal/data/
   peer_store.dart) and builds debt screens locally (merchant_api.dart);
   chat history + offline outbox on device; server purges read chat.
6) Exchange rates fetched by the device — core/services/currency/
   public_exchange_rates.dart (5 public sources + 2dec.net), used by the
   currency engine and Business report rates; server only fallback.
7) Server write guard — backend/app/core/business_local_guard.py refuses
   Business REST writes for device branches / local-mode orgs.
