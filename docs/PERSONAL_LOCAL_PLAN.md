# Personal → device-only (server = relay) — plan (2026-11-25)

Owner rule: ALL Personal user data lives only on the user's devices (encrypted). The server only relays changes between the same user's devices and deletes them once every destination acknowledged. Same policy as Business.

## Findings
- Personal mirror `personal_entity_cache` is in plain sqflite `fyona_erp.db` (lib/core/database/tables.dart:615, database_helper.dart). Trees (financial_tree_storage.dart) and account types (account_type_store.dart) are in SharedPreferences. Only Business uses SQLCipher (directory_database.dart:100-140).
- Server tables (backend/app/domain/entities/personal_entities.py): bank_accounts, transactions, savings_goals, debts, debt_payments, budgets, budget_categories, recurring_transactions; + sync_batches/sync_logs entries (personal_sync.py:99).
- Write path: screen → personal_providers → PersonalFinanceService → PersonalCacheRepository.commitOfflineWrite/commitMirrorOnly/commitTransferAtomic (personal_cache_repository.dart:552,678,713) → outbox → SyncEngine._replay (sync_engine.dart:439-700) → REST /personal/finance/* ; pull via /sync/pull.
- Server-only reads in client: budget aggregation (service ~2070), debt payments (~1665), categories (~2502), ensureCashAccounts (~706), resetAccount (~1993), restore (backup_service.dart:1812).
- Server consumers: Sara SaraContextBuilder (sara_agent_service.py:1131-1398), server ToolExecutor reads (2171-3060), prepare_personal_banking (3125), sara_analytics.build_financial_analytics (206-360); workers tasks.py:383 (_check_low_balance), 469 (_check_budget_alerts); admin_personal.py:152-622; /personal/finance/reset (3027), restore (3365); backups.py (plaintext JSON snapshot).

## Stages
1. Encrypted Personal ledger (SQLCipher, per user, same key-store pattern as directory_database) behind the existing PersonalCacheRepository API; one-time move from plain cache + prefs (trees, account types, rates); copy → verify → wipe plain rows.
2. Backend personal relay: backend/app/domain/services/personal_relay.py + api/v1/personal_relay.py, modelled on business_relay.py (per-user seq, inbox per other replica, delete on ack keeping id/seq tombstone, RETENTION 90d + resync_required, snapshot request/serve/applied, retire, replicas). Separate tables personal_relay_*. Auth get_current_user_uuid. Opaque payloads.
3. Client relay runtime: each commit* mutation set = one op (same transaction) into ledger outbox; push/pull loop (10 s, reconnect, resume); apply in seq order; idempotent op_id; counters as deltas; other fields last-writer-by-seq; tombstones win; new device → snapshot request, else local backup restore. Behind a flag; old server sync stays parallel until cutover.
4. Make server-only reads local (aggregation, debt payments, categories, ensureCashAccounts, reset, restore).
5. Sara Personal device loop (generalize BusinessDeviceLoop; server returns device_calls for personal read tools when header x-fyona-device-sara + local mode; /ai/continue); port analytics to Dart (personal_analytics.dart) with parity tests.
6. Cutover: personal_local_mode.py flag, personal_local_migration.py (status/export stable bytes + digest/ack/purge children-first incl. sync logs), client drain old outbox → import baseline → verify → ack → purge; personal_local_guard.py refusing personal writes for local users; min app version gate; admin_personal counts only/410; workers skip local users.
7. QA soak then purge.

Owner decision (2026-11-25): leave backups (server and local, Business and Personal) untouched for now; the owner will give a full backup design after the sync/architecture work. Do not change backups.py or backup_service behaviour beyond keeping restore working with the new ledger.

## Stage 2 done — relay API (prefix /api/v1/personal-relay, Bearer JWT, extra fields forbidden, responses {success,message,data})
Limits: MAX_PAYLOAD 16 MiB/op, MAX_SNAPSHOT 48 MiB, MAX_BATCH 200, RETENTION 90 d. Payload = base64 string (ciphertext) or JSON; pull always returns base64.
- POST /register {replica_id} → {replica_id, resync_required, head}. First replica false; later new/rejoined replicas true.
- POST /push {replica_id, items:[{id: uuid, kind:"ops", payload}]} → {items:[{id, seq}]}. Retry returns original seq (tombstone). Lone device: payload dropped, tombstone kept.
- POST /pull {replica_id, wait?0-25, limit?1-200} → {items:[{id, seq|null, kind, replica_id(author), payload b64}], drained, head, resync_required}. Control items first, then ops by seq; never own ops.
- POST /ack {replica_id, ids} → {purged}. Last ack deletes payload (id/seq tombstone stays).
- POST /snapshot/request {replica_id} → {requested, resync_required}; other live replicas get kind "snapshot_request" payload {"replica_id": requester}. None live → resync cleared, requested=false.
- POST /snapshot/serve {replica_id, target, payload} → {sent}; only to a waiting replica; one pending per target; target receives kind "snapshot", seq null.
- POST /snapshot/applied {replica_id} → {} (deletes snapshot blob + requests, clears resync).
- POST /retire {replica_id} → {}; kicked sessions auto-retire.
- GET /replicas → counts/metadata only.
Client must: put last applied seq inside snapshot blob; receiver skips ops ≤ that seq; if resync stays true, request snapshot or offer local backup restore.
Files: backend/app/domain/services/personal_relay.py, api/v1/personal_relay.py, tests/unit/test_personal_relay.py; hourly purge task purge_personal_relay.

## Stages 3–4 done — client relay runtime + local reads
Flag: `PersonalRelayConfig` (lib/features/personal/data/ledger/personal_relay_config.dart) — on for QA builds (`FYONA_DIRECTORY_PILOT=true`), override with `--dart-define=FYONA_PERSONAL_RELAY=true|false`. Off → no capture, no runtime, old behaviour (incl. server cash check, account-type peer relay).
- Capture (personal_relay_store.dart `PersonalRelayCapture`): every user-intent ledger commit writes ONE op into `personal_relay_outbox` in the same SQLite transaction: commitOfflineWrite / commitMirrorOnly / commitTransferAtomic / commitLocalRow (categories) / wipeNamespaces (reset) / PersonalLedgerKv (trees) / account types / rates (PersonalRepository) / backup restore (ledger part; split ≤4 MiB/op). Server-mirror writes (upsertItem/removeItem/replaceCollection, SyncEngine pulls/remaps) record nothing.
- Op: `{v:1,id,us,c:[{t,id,k:i|u|d,data,f:[changed fields],d:{counter:delta}}]}`; t = entity type | `_kv` | `_rate` (id `FROM>TO`) | `_acct` (account types, `data:{t,at}`). `_sync_version` never travels.
- Rules: counters balance / current_amount / paid / budget spent as deltas (rounded 1e-6; a create of a row already present adds nothing); other fields per-field last-writer-by-seq with per-field clocks + "pending" (unsent local) fields in `personal_relay_rows`; delete = tombstone (`personal_relay_rows.deleted=1`, rows removed from personal_rows) that wins; derived goal is_completed / debt remaining+paid recomputed; idempotent by op id (`personal_sync_log`) and snapshot floor; apply never records ops and never touches the old outbox.
- E2E: payloads sealed with a per-user data key (ChaCha20-Poly1305, AAD = op id / snapshot target); key ring transferred device-to-device by `key_request` (X25519 pub) / `key_grant` (HKDF-SHA256 KEK) plain-JSON ops. First replica (register resync=false) makes the key; nobody answering for 30 min → own key (keys merge later). Residual risk: an actively malicious server (or stolen login) can register a fake replica and be granted the key — follow-up: device approval / safety code.
- Snapshot: served only with empty outbox, nothing parked and a drained inbox; `{seq: last applied remote seq, own:[local ops seq>seq], rows(+clocks), tomb, kv, rates, acct}`; receiver replaces, keeps + re-emits local-only rows, re-applies own ops not contained, sets floor. No answer in 30 min → `gave_up` (keep local data; a late snapshot only fills gaps). Everything received is parked first, then acked, then applied in order (waits for key/snapshot).
- Runtime: personal_relay_provider.dart (`PersonalRelayRuntime`, mounted in app_router around PeerRelayRuntime): push on every local write, long-poll pull, every 10 s, on reconnect/resume; skipped offline (incl. very poor link). After apply: reload personalFinance/budget/recurring/category/tree providers; after a snapshot: sweepDuplicateCashAccounts (survivor = smallest id when all zero, same on every device).
- Stage 4: getBudgetAggregation = `computeBudgetAggregation` (port of the server endpoint); getDebtPayments / getCategories / resetAccount id lists from the ledger; ensureCashAccounts (relay on) checks the ledger only and creates nothing while waiting for a snapshot.
- Stage 6 must: stop the old Personal SyncEngine push/pull + `_safeList` server fetch/background refresh for local users (during the transition server pulls are absolute and can briefly override relay deltas — converges to the server); drop the server reset/restore/bulk calls; keep handling old `account_types*` peer-relay kinds one more release then remove; consider pruning `personal_sync_log`.

## Stage 6 done — cutover (device-only Personal)
Flag: backend `personal_local_mode.py` — on for the QA service (QA invites or `FYONA_QA_REMOTE=1`; `FYONA_QA_LOCAL_PERSONAL=0|1` overrides; the pilot launcher passes it and `FYONA_PERSONAL_LOCAL_GRACE_HOURS` through), every user of that service is local. Client: `PersonalLocalMode.active` = relay builds (`PersonalRelayConfig`) unless the server answers 404 on `/personal-local` (then the old sync stays fully on). Builds send `X-Fyona-Personal-Protocol: 6`.
- Migration (`personal_local_migration.py`, `/api/v1/personal-local`, Bearer = current user): table `personal_local_migrations(user_id PK, snapshot_id, digest, body, created_at, imported_at, purge_after, purged_at)`. GET /status {local, needed, imported, rows, …}; POST /export {snapshot_id, digest, body b64} — canonical JSON (sorted keys) of the user's live rows of the 8 tables in the REST list shapes the app keeps (budget categories inside their budget and as their own list; debt `status` without the date-dependent «overdue»), `counts`, `balances`; sha256 digest; the first export is kept byte-for-byte until acked, later exports rebuild the same bytes from the frozen rows; POST /ack {snapshot_id, digest} → imported_at, purge_after = now + GRACE (168 h default), body cleared; a later ack changes nothing. Purge (hourly: Celery `purge_personal_local` + in-process `workers/personal_maintenance.py` for services without beat): after purge_after, deletes the user's rows children-first (transactions, debt payments, budget categories, recurring, goals, debts, budgets, accounts, soft-deleted included) + their sync_logs/conflict_logs/entity_versions (by the user's own row ids) + sync_batches only when the organization has no other user; idempotent; nothing of Business or other users.
- Guard (`personal_local_guard.py`, after the Business guard): `/api/v1/personal/finance/*`, `/sync/push`, `/sync/pull` for local users: no protocol header → 409 `update_required`; once an export exists → writes 409 / reads 410 `personal_local`. Exempt: `/personal-local`, `/personal-relay`.
- Sara: Personal Sara without `x-fyona-device-sara` → 409 `update_required` (query, attachment, continue); always device mode; server-table context/tool/analytics paths deleted (`resolve_period`/`convert_net_totals` kept). `ToolExecutor._exec_create_transaction` (server write, unreachable from the Personal loop — create goes through prepare/confirm on the device) is still there for its existing unit tests; remove with them.
- Workers: `_check_low_balance` / `_check_budget_alerts` read no Personal table when the mode is on; the device's smart notifications raise low balance (≤ 0, once per account per day) and budget over (existing), deterministic.
- Admin: `/admin/personal/stats` counts only (users, relay devices, migration counts); every per-user data route 410 «data lives on the user's devices». No admin web code in this repo.
- Client cutover (`personal_local_cutover.dart`, run by `PersonalRelayRuntime` on every wake until done): drain the old outbox → /status → /export (waits until the relay inbox is drained and nothing is parked) → import in ONE ledger transaction, upsert by id, never relay ops: missing rows added; plain server copies (no relay history, no unsent old write) take the server values (`_sync_version` kept); rows with relay history / unsent old writes / relay tombstones kept → verify (digest, format, user, counts, every listed row present or tombstoned, balance of every written account) → /ack → old outbox rows older than the first relay op become relay ops (row as it is here or its delete), old outbox emptied → state `done` (ledger meta `personal_local_cutover_v1`). Resumable at every step; offline: silent retry; other failures counted, calm notice after 3. 410 on export (already purged) → done (the other devices / snapshot bring the data). After `done`: SyncEngine never runs, commits write no old-outbox rows (relay op only); a pending old outbox hit by `personal_local` is converted the same way.
- Stopped for local users: SyncEngine pulls (also before the cutover; it only drains), `_safeList` server fetch / background refresh, server reset, bulk restore and the backup server layer (backups otherwise unchanged), server verification in SaraVerificationGateway, account_types peer-relay push (incoming `account_types` still merged one more release).
- Prefs → ledger (copy → verify → wipe): `cash_vault_<id>` (ledger kv); reminder stores `debt_reminders_v2`, `recurring_reminders_v2`, `sara_smart_reminders_v1` (`personal_reminder_store.dart`, ledger key `reminders:<key>`): SharedPreferences keeps only a redacted boot copy (when, request code, kind, id, route, generic localized text, `_r:1`) so the Android BootReceiver still re-arms alarms; it uses the copy's title/body when `_r` is set. Without an open ledger the plain store is used and moved next time. Smart-notification settings (on/off, time) hold no financial data and stay in prefs.
- UI: `PersonalLocalNoticeBar` (in PersonalRelayRuntime): once when a new device found no other device (`gave_up`) → suggest restoring a local backup (button → /personal/backup); old-data move still retrying; «update the app» on any `update_required`.
- Tests: backend test_personal_local_migration.py, test_personal_local_guard.py (+ sara tests); Flutter personal_local_cutover_test.dart, personal_local_old_sync_test.dart, personal_local_prefs_notice_test.dart.
- Existing QA users: nothing is deleted until a device of the user running this build has imported and acknowledged the export; then 7 days of grace, then the hourly purge. Users who never open a new build keep their server rows (frozen only after an export; old builds get «update required»).
